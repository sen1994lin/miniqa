# AI 辅助测试工作流（miniqa 视角）

> 思路：**AI 负责"生成骨架 / 穷举用例点"，人负责"测试策略 / 断言质量 / 业务边界"把关。**
> 工具只解决"可被规则穷举"的部分，真正值钱的是你对业务隐含规则和质量风险的判断。

## 1. 用 `miniqa.gen` 先出骨架（零成本、免 key）

```bash
python -m miniqa.gen sample/app/calculator.py -o sample/tests/test_calculator_gen.py
```

它基于 AST 解析出所有函数，生成 `@test` 占位用例，你再补断言。

## 2. 让 AI 帮你"补用例点"的提示词模板

把下面这段直接丢给任意大模型即可：

```
你是一个资深测试工程师。下面是 Python 源码：
<粘贴源码>

请用 miniqa 框架（@test 装饰器 + assert_equal / assert_raises）为它生成测试用例，
要求覆盖：1) 正常路径 2) 边界值 3) 异常输入（如除零、负数、None）。
只输出测试代码，不要解释。
```

## 3. 把"手工测试用例"转成自动化

```
下面是一段手工测试步骤（自然语言）：
<粘贴步骤>

请把它转成 miniqa 的 @test 函数，用 assert_equal 表达预期结果。
```

## 4. 人要做的关键判断（AI 替代不了）

- 哪些场景是"看起来对其实反人类"的界面/交互问题；
- 分布式 / 并发下的"幽灵缺陷"（时序错乱、数据竞态）；
- 业务隐含的"潜规则"，以及安全 / 合规边界。

> 结论：AI 把测试员从"点工"变成"质量架构师"。本仓库就是这一转型的实物证据。
